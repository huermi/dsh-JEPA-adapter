# 2026-08-18 工作日志

## JEPA × DSH 深度集成方案（辩论委员会产出）
- 交付文件：`JEPA×DSH深度集成技术方案_辩论委员会.md`
- 形式：四位专家（架构师/JEPA/DSH/质疑者）六轮辩论 → 收敛为 7 章可落地技术方案。
- 关键结论（可复用）：
  1. **JEPA 定位 = 新 `JEPA-Loop` 潜空间主循环，LLM 降级为 Text Codec + 降级备援**（不替代 LLM）。
  2. **双总线**：文本总线（兼容层）+ 潜空间总线（决策层），LLM 是唯一翻译器；跨空间只做**离散锚点对齐**（动作码本/目标原型/状态编码器），不做连续向量互映射——呼应 huermi 的"离散标签联觉"立场。
  3. **动作对齐三段式**：`actor→连续动作潜→(最近邻)工具码→(LLM)参数JSON`；参数不连续回归，结构化生成交给 LLM。
  4. **三级可塑性**（实时训练核心）：T1 默认冻结主干只训 head/码本/投影 → T2 触发式 LoRA 残差微调（新世界动力学）→ T3 离线合并。
  5. 遗忘控制复用 CL-JEPA 结论：EMA 目标编码器 + 原型重放 + LoRA 隔离（EWC 只用于小 head）。
  6. 思考适应性 = 预测误差 E 驱动三杠杆（搜索深度/探索权重/在线微调触发）。
  7. 事实锚点：V-JEPA 2 实为 **1.2B**（ViT-L 300M 编码器 + ViT-S ~22M 预测器，1M+ 小时视频 + 62h Droid 机器人数据）；潜空间 MPC rollout 极便宜（22M 预测器单步 <2ms），主循环延迟 ~0.4–1.2s。
- 待验证假设（A1）：跨模态潜对齐质量、潜空间 MPC 在离散工具环境的 rollout 稳定性——P1/P2 准入门槛，失败则降级为"JEPA 仅做世界模型异常检测 + LLM 继续规划"。

## JEPA × DSH 方案 v2 修正版（第二轮辩论）
- 交付文件：`JEPA×DSH深度集成技术方案_v2修正版.md`
- 触发：用户审查 v1 后列出 6 项缺陷，要求逐条修正 + 8 轮辩论 + 硬性约束。
- v1→v2 关键转向（可复用结论）：
  1. **默认纯文本/JSON**（不依赖视觉）：状态编码器 = 冻结 ~60M 文本编码器 + 字段聚合，呼应 LLM-JEPA（arXiv:2509.14252）——JEPA 价值不依赖视觉，在于"预测连续潜向量而非词元"。
  2. **稀疏层级编码器**：L0文本(60M,冻结)/L1字段(256d)/L2状态(128d)；稀疏靠"增量编码 + 字段原型缓存"（只重编码变化字段），默认激活 ~5M，触发低层 ~17M；低层触发由"全局E + 字段注意力熵 + L1残差方差"三信号驱动。
  3. **MoE 预测器**：8专家×50K + top-2 路由，总 0.42M、激活 100K；预测残差 Δs 防坍缩；漂移控制 = 残差 + EMA target + 集成方差截断 + 路由一致性正则。预测器小是因为只预测 128 维潜残差（"世界模型"降格为局部潜动力学近似，MPC 够用）。
  4. **模板+分类器优先参数解码**：enum/bool/number 走最近邻原型分类，仅 free-text 走 LLM；HTTP 请求常规 <5ms。分类器 = 共享槽位注意力 + 槽位原型库（零训练扩展）。
  5. **秒级适应精确分层**：A 分布漂移（LayerNorm 统计 EMA 重估 + 原型 EMA，真·秒级非梯度）/ B 新动力学（head-only 梯度，秒~分级）/ C 主干 LoRA（分钟级）。快速权重 = 增量岭回归（64×64 闭式 μs 级）。
  6. **渐进式路线（D6）**：P0=JEPA 预测辅助（LLM 生成 top-K 候选，JEPA 排序）；升级触发 5 条定量指标；灰度 10→30→100% 掉 3% 回滚；止损线=连续两轮 P@1 无提升→降级"世界模型哨兵"。
  7. 量化：单步主循环延迟 ~20–60ms（≪1.5s），显存峰值 <6.5GB（≪20GB）；LLM 永不整体移除（保留子目标/自由文本/兜底）。
- 教训（对话方法）：质疑者"用高层误差判断是否触发低层"是逻辑悖论（用近视眼判断该不该戴眼镜）——修正为三信号驱动；"秒级适应拿 BN 重估糊弄"被戳穿后精确分层为 A/B/C。

## JEPA × DSH 方案 v3（轻薄本适配，第三轮辩论）
- 交付文件：`JEPA×DSH深度集成技术方案_v3轻薄本版.md`
- 触发：用户纠正重大硬件误解——**20GB 是模型总参数存储上限（FP16≈10B 参数），不是显存**；本机是轻薄本，显存极小。要求总 10B / 激活 <100M / 显存 <2GB / 单步 ≤1.5s。
- 核心架构转向（关键，可复用）：
  1. **"总参数大、激活小"的极端稀疏**：层级稀疏专家池（字段 2B + 预测 4B + 动作 1B + 结果模型 2B + 目标 0.25B + 路由 0.75B ≈ 10B）驻留磁盘/内存，三级级联 top-1/2 路由，激活默认 ~15M、最坏 ~35M。专家粒度做小到 0.5M（CPU 前向 0.5–2ms），大量专家留内存 CPU 按需算，不需 GPU。
  2. **专家卸载 + 分级存储**：磁盘 20GB 全量、内存热专家 LRU 1GB、活跃 <100M；路由预取 + 4KB 页式 + MVCC 快照读。扩容只涨磁盘不涨延迟（稀疏化红利）。
  3. **v2 五缺陷逐一修正**：D1 字段级专家池替代 60M 稠密 L0（真正字段级稀疏）；D2 P0 真实账本（LLM 短候选 8–15 token + JEPA 模板解码，排序对象是 JEPA 先解码的完整动作）；D3 快速权重低秩扩展到每层；D4 工具结果模型三档（热门 MLP/冷门 LLM 先验编译到可解释槽位层/零数据截断+试探）；D5 GRU 进展潜 h_sub 跨时间抽象。
  4. **轻薄本硬事实**：0.5B int4 LLM CPU 5–15 token/s → 纯 LLM 完整生成 4–10s 不可用。JEPA 的定位从"优化"升为"让 Agent 在轻薄本可行"——稳态（动作缓存命中）30–50ms，未命中 1–3s。JEPA 在 P0 第一价值是参数解码（LLM 替代不了），排序是第二价值。
  5. **反过度工程让步**：极端稀疏/专家卸载/10B 是 P3 后的渐进优化，MVP（P0–P2）用 dense 1B 起步，先把"LLM 短候选 + JEPA 参数解码 + 排序"跑通。
- 质疑者本轮最尖锐交锋：①"600 倍稀疏比业界才 10-50 倍，是类幻想"→ 诚实降为渐进扩容终点；②"语义规则→潜空间维度赋值是幻想"→ 规则改作用于可解释槽位层（离散 key-value）；③"P0 JEPA 被边缘化"→ 参数解码才是 P0 第一价值；④"为 10B 虚荣数字过度工程"→ MVP dense 1B 起步。
